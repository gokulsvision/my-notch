A browser in your notch. Click the notch. Watch the video. Tuck it away.

Atoll turns the MacBook notch into a live surface. This fork adds one more tab — a real WebKit browser — so you can watch a video or read a timeline without switching windows, then hide the notch while the page keeps playing.

What's added

Strictly additive. Nothing upstream changes.

Every existing Atoll feature works exactly as before. The fork adds a browser tab and the plumbing to make it feel native.

01

Browser tab

A globe icon in the notch tab strip, opening a real WebKit browser with an omnibox, tab strip, and page zoom.

02

Panel sizing

S/M/L/XL presets plus a drag handlebar for any height in between. Drag down and the panel's bottom edge follows 1:1.

03

Pin & auto-close

Pin keeps the panel open. Unpin and it closes a configurable delay after your cursor leaves — so a video is never interrupted.

04

Session that survives

Tabs and logins persist across notch cycles and app restarts. One YouTube login, indefinitely.

05

Dark by default

Each webview is pinned to dark appearance, so prefers-color-scheme matches on every site regardless of system setting.

06

Smart omnibox

A full URL navigates, a bare domain gets https://, anything else is a search. DuckDuckGo default, Google optional.

The hard part

Making a browser behave inside a notch.

A notch panel can close, resize, and tear down at any moment, and SwiftUI rebuilds views aggressively. These are the problems that took the real work.

One webview per tab, forever

Recreating a WKWebView reloads the page and drops session state, so each tab owns exactly one for its lifetime and the SwiftUI wrapper merely re-binds the existing instance. Hidden tabs stay alive off-screen, so switching tabs never reloads anything. Tabs cap at four, recycling the oldest inactive one to bound memory.

Surviving the notch lifecycle

The tab list and its webviews live on a shared singleton that outlives individual view lifecycles. Closing the notch, auto-closing it, or restarting the app never destroys a page — which is the entire point: leave a video playing, tuck the notch away, come back to it.

Gesture interception

The drag handlebar consumes mouse events with local NSEvent monitors. Atoll installs a notch-level drag gesture that swallows every mouse-down before SwiftUI would see it, and a SwiftUI drag gesture dies mid-drag once the window resizes underneath it. AppKit event streams are immune to both.

Resize math that can't drift

The panel's bottom edge is simply the cursor's distance from the screen top. No anchors, no accumulated deltas — so the window moving under the cursor can never cause drift.

One source of truth for height

Three separate call sites must agree on the notch height, and they all read the same value. The hosting view needs an autoresizing mask or the window grows while content stays stale; the browser pins to one explicit height instead of filling, which produced ambiguous layout inside the notch's stack.

Freezing the jitter

While the browser is open, the usual notch-resize signals are frozen. Live web content perturbs SwiftUI's intrinsic sizes and caused constant window jitter — so only tab switches, presets, and handlebar drags may move the window.

Get started

Build it

Needs Xcode 16+ (built with Xcode 26.6 on macOS 26) and the Metal toolchain. The app bundle keeps the upstream Atoll name.

xcodebuild -downloadComponent MetalToolchain
xcodebuild -project DynamicIsland.xcodeproj -scheme DynamicIsland \
  -configuration Debug build \
  CODE_SIGN_IDENTITY="Developer ID Application" \
  DEVELOPMENT_TEAM=<your-team-id> \
  CODE_SIGN_STYLE=Manual

Known limitations

  • Passkeys / WebAuthn can't present from the notch window — use a password or the cross-device QR flow.
  • Page zoom is a magnification scale; fit-page is a fixed ratio rather than computed per page.
  • DRM video follows WebKit's normal rules; the panel doesn't bypass it.
